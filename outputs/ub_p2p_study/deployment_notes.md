设计提案，尚未实现；组件职责是本次方案约定，不是对现有产品功能的确认。2026-09-28 修正：分发目标为每个接收节点的本地 DRAM 完整包就绪，SSD 仅可选后续留存。

## 数据路径与边界

1. 权威制品预热到 OM DRAM；OM 与业务节点同构。预热准备单列；主计时从 OM 向最初无副本的 N 个业务节点分发开始，节点 1 收到块后即可参与转发。
2. 接收节点定位候选 Peer、获取读授权，由 Agent 拉取分块。图中绿色箭头是字节方向；采用 URMA READ 时，请求方向相反。
3. 校验完成的块才进入可供数目录；Peer 不必等待整个模型收完才供出已校验块。缓存与注册缓冲之间可能有复制，零拷贝不是既定能力。
4. 当前计划先实现 TCP baseline，再替换 UB 数据后端；少量控制 RPC 可继续走 TCP。图中链式转发对应首版实验，不排除后续多源/拓扑感知选源。
5. 本图 N 个业务节点均为接收者，OM 额外作为初始源，与当前同构仿真 N 的口径一致。N=50 表示 50 个接收节点；若整个集群含 OM 共 50 台，则 N=49。
6. 主计时止于全体节点 DRAM 完整包就绪；SSD 后续留存与模型加载/服务 ready 单列，不等待 SSD 才确认模型包就绪。

业务节点同时担任 Peer 需验证 CPU、DRAM 收发和在线推理负载竞争；每个节点须预留完整包容量。一个权威版本可以有多个缓存副本；备份、持久化和副本数应分别定义。
